## 4. 缺陷评估：改密接口运行时被锁死

### 4.1 现象

`POST /api/v1/admin/matchmaker/auth/change-password` **对任何调用者都返回 403**，包括拥有全部权限的后台管理员。

已用脚本直接验证三闸判定链：

```
URL 关键词映射 (_matchmaker_admin_permission) → None
豁免白名单   (_is_permission_exempt)          → False
端点权限声明 (@declare_permission)             → 无
⇒ get_current_matchmaker_admin 命中 fail-closed 分支，抛 403「后台接口缺少权限声明」
```

### 4.2 根因

`app/api/routes/matchmaker_admin.py:85` 的路由只依赖 `get_current_matchmaker_admin`，但：

- 其路径不命中 `app/api/dependencies.py:404` 任何关键词分支；
- 不在 `PERMISSION_EXEMPT_SUFFIXES`（仅含 `/admin/matchmaker/auth/me`、`/admin/matchmaker/auth/logout`）；
- 没有 `@declare_permission` 装饰器。

业务逻辑本身没有问题：`FOR UPDATE` 取行、`verify_password` 校验、bcrypt 重哈希、写 `business_audit_log` 审计，均在 `db.commit()` 前完成。**缺陷纯粹位于权限判定链，不在业务实现。**

### 4.3 引入时间（已用 git 定位）

| 提交 | 日期 | 事件 |
|---|---|---|
| `bafa20f` | 2026-10-04 | 引入精确后缀豁免名单 `PERMISSION_EXEMPT_SUFFIXES`，并新增本覆盖测试 |
| `d8cbcd1` | 2026-10-13 | **新增改密路由** → 立即构成权限盲区，覆盖测试开始失败 |

**评估结论**：测试先存在、路由后加入 ⇒ 这是一次**真实回归**，不是测试误报；不是历史遗留问题。

### 4.4 安全性定性：不是越权漏洞，是功能失效

**这是本报告最需要避免误判的一点。**

- fail-closed 分支工作正常——未命中的后台路由被**拒绝**而非静默放行。因此**不存在越权读写路径**，`test_unknown_routes_are_fail_closed` 亦通过。
- 历史风险（对照 `dependencies.py:507-508` 注释与测试 docstring）是"早期实现使用 `"/auth/" in path` 子串匹配，导致 `/admin/members/auth/realname-reviews` 等业务路由被误判为豁免"——**该 fail-open 问题已修复**，本次发现的是修复的副作用，不是回退。

真实危害有且仅有三条：

1. 后台账号**无法自助修改密码**（所有角色）；
2. 该接口已在 `docs/api/后台账号修改密码.md` 对外承诺，前端按此联调会得到 403；
3. 唯一涉及它的测试 `tests/test_admin_password_change_contract.py` **只断言路由已注册**，不覆盖运行时行为，因此缺陷能长期不被发现。

### 4.5 处置方案对比（本次均不执行，仅评估）

| 方案 | 做法 | 安全性 | 代价 | 评估 |
|---|---|---|---|---|
| **A. 纳入认证类豁免** | 加入 `PERMISSION_EXEMPT_SUFFIXES` | 访问面从"无人可用"放宽到"任意已认证后台账号仅可改**自己**密码"。句柄锁死 `current.account.id`，**无横向越权面** | 改 1 行 + 同步修订覆盖测试中的精确集合断言 | ✅ **推荐** |
| **B. 声明业务权限** | `@declare_permission("matchmaker.account.manage")` | 无放宽 | 改 1 行 | ❌ **不推荐**。改密是自助操作，要求业务权限会导致低权限账号无法轮换密码，反而逼出弱密码/共享账号 |
| **C. 新建专用权限码** | 新建"任意已认证后台账号"权限并全量播种 | 最精确 | 需改权限种子表 + 迁移 + 连带测试 | ⚠️ 影响面远大于收益 |
| **D. 维持现状** | 不动 | 最保守 | 保留 1 项失败测试与失效接口 | ⚠️ 可行，但需向产品确认后台账号体系口径 |

### 4.6 关键约束：不能只加豁免

交接稿 §2.7 原文："针对改密接口实际验证匿名、普通用户及相关后台角色权限，**不能只添加测试豁免**。"

评估认同该约束。仅把路径加进豁免名单让测试变绿，等于用白名单掩盖运行时行为未经验证的事实——这正是本缺陷得以发生的原因（`test_admin_password_change_contract.py` 只测注册不测运行时）。

**任何方案都须同时补齐行为级测试**：匿名 → 401、C 端普通用户令牌 → 401、有效后台令牌 → 204 且旧密码失效、旧密码错误 → 400。

## 6. 记忆系统处置评估（回答"要不要删"）

### 6.1 结论

**不可整删。** 交接稿转述的"不弄就删掉、只保留当前功能"在代码事实上不成立。

### 6.2 量化影响面

| 指标 | 实测 |
|---|---|
| 记忆模块自身代码 | 5,493 行 / 13 个文件（`app/services/ai/memory/`） |
| 非记忆目录中引用它的 app 文件 | **14 个** |
| 专门覆盖它的测试文件 | **25 个**（`tests/test_ai_memory_*.py` 等） |
| 当前读取模式默认值 | `legacy`（`app/core/config.py:176`） |

### 6.3 必须区分两层职责

**第 1 层：新读取路径（可选）**
`legacy` / `shadow` / `memory` 三态迁移。实际分支点全仓仅 4 处：

- `app/services/ai/features.py:686`（解析器）
- `app/services/ai/compatibility.py:1143`
- `app/services/ai/recommend.py:285 / 420 / 485 / 874`
- `app/services/ai/search.py:1782 / 2319`

默认 `legacy` 已**等价于冻结**该层。这一层才是"可以不做"的部分（对应交接稿 M-04）。

**第 2 层：授权 / 撤权 / 清理 / 投影生产 基础设施（不可删）**

被以下主链路直接依赖：

| 消费方 | 引用内容 | 职责 |
|---|---|---|
| `app/services/ai/consents.py` | `consent_producers` + `purge.current_owner_sequence` | 授权/撤权生命周期 |
| `app/services/ai/profile.py`、`continuous_memory.py`、`journey.py` | `MemoryPolicy` / `MemoryService` | 授权校验 |
| `app/services/ai_advisor.py` | `CounselorMemoryAdapter` | 军师上下文 |
| `app/services/ai_avatar.py` | `consumers` | 分身上下文 |
| `app/services/derivation_outbox.py`、`workers/ai_worker.py` | `purge_memory_for_owner`、TTL/retention 清理 | 删除与留存的合规兜底 |

删除第 2 层会**同时破坏** profile、search、recommend、军师、分身的隐私边界，并让 25 个测试文件失去被测量对象——即交接稿 §1.3 明确要求"保留"的"按用途授权、投影与授权代际"能力。

### 6.4 建议口径

**不删 + 第 1 层冻结在 `legacy`**，把原 M-04（记忆模式迁移）降级为"暂缓并记录复评条件"。这样既省掉迁移与回退验证成本，又不拆隐私地基。

若确要缩减维护面，可行路径是 **§6.3 第 1 层单独摘除**（涉及 4 处分支点 + 相关迁移/回退代码），而非整体删除。
