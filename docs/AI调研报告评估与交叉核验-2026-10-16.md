## 三、三处实质问题

### 3.1 【严重】测试状态整体陈旧，把三周前的记录当作当前状态

报告在"测试现状"与"主要风险"两处写道：

> 存量测试未收绿：2026-09-25 门禁记录全量 2129 passed / 6 failed（pricing 配置契约、标签目录漂移、行政区编码、语音 WS 门禁夹具等）+ Ruff 56 errors

两项具体问题：

1. **失败集合已完全轮换。** 报告列出的 6 项（其中 m4_m7 迁移资产还已在 09-27 补齐）**没有任何一项**出现在当前失败列表中。当前失败是：`test_ai_governance_contracts`、`test_memory_docs_contract`×5、`test_community_demo_seed`、`test_voice_cleanup`，以及被漏报的第 9 项。
2. **Ruff 数字已过时。** 当前 27 项全部为**非安全性**问题（未使用的 import / 未使用的局部变量 / 模块级 import 位置），**无 F821（未定义名）**。报告沿用 56 这个数字，会让"技术债"的分量被高估一倍。

**根因**：该报告**没有运行测试套件**。它自己诚实地写了"交接文档的'全量 75/92、17 失败'是原交接历史记录，本次未重跑"——但随后在结论里仍以 09-25 的历史数字描述当前状态，这就从"诚实标注未重跑"滑向了"以历史数据冒当前数据"。

### 3.2 【严重】漏报了当前唯一的真实新回归

该报告从头到尾**没有出现** `test_admin_permission_coverage`，也没有提及 `POST /api/v1/admin/matchmaker/auth/change-password` 的权限盲区。

而这是本机全量测试中**唯一一项非环境导致的失败**：该测试是纯静态 AST 测试，不依赖数据库/Redis，单跑 1.17s 完成，因此不可能归因为环境。

它在"主要风险"里写的是"6 项存量测试失败与 56 项 Ruff 告警未收绿"——**恰好把真实存在的那一项替换成了六项已经不复存在的**。这是本次评估中最需要纠正的一处：如果按该报告的结论排期，会先去做一批已经收绿的旧失败，而把唯一在流血的问题漏掉。

### 3.3 【中等】"记忆系统 生效 0%"的表述会误导删除决策

报告结论表写：**记忆系统｜机制 ~90% / 生效 0%**。

这个"生效 0%"只对**新投影读取路径**成立（`legacy`/`shadow`/`memory` 三态默认 `legacy`，确实未在读取路径上生效）。但它会被读成"记忆系统整体是死代码"——而这正是你同事"不弄就删掉"那句话想做的事。

实际上记忆模块被 **14 个非 memory 目录的 app 文件**依赖，其中**授权 / 撤权 / 清理基础设施是当前就在生效的**：

- `consents.py:552`、`profile.py:4512`、`lifecycle.py:119` 都在撤回事务内取 owner 序列水位；
- `profile.py`、`continuous_memory.py`、`journey.py` 用 `MemoryPolicy`/`MemoryService` 做授权校验；
- `ai_advisor.py`、`ai_avatar.py` 用其对话上下文适配器；
- `derivation_outbox.py`、`ai_workers` 用其清理与 TTL 兜底。

准确表述应是：**"新投影读取路径未生效；授权/清理基础设施已生效且为主链路依赖"**。报告自己在正文里其实讲对了（明确写了"删除等于重写这些能力的授权边界"），但结论表那个"0%"与正文相悖，且恰好以最容易被断章取义的形式呈现。

### 3.4 【轻微】内部自相矛盾与不可证伪的百分比

- **"免费模型接入 = 未实现（以 Mock 替代）"**（标注汇总）与同报告结论表 **"大模型接入 ~80%，Mock/低价 Provider 双轨可用"** 相矛盾。前面还正确说明了 deepseek（`deepseek-v4-flash`）、dots 是真实可用的低成本 Provider。准确的表述是"**无免费模型专用分支；零成本路径 = Mock；低成本真实通道 = deepseek/dots**"。
- 全部完成度百分比（语音 ~85%、大模型 ~80%、记忆 ~90%、画像 ~85%、搜索 ~90%）**没有给出计算口径**，无法复核也无法证伪。作为汇报语言可以，但不应被当作验收依据。
