- **问题**：`POST /api/v1/admin/matchmaker/auth/change-password`（[app/api/routes/matchmaker_admin.py:85](../../../Xuanshiai/xuanshiai/app/api/routes/matchmaker_admin.py)）对**任何调用者**恒返 403。路由无 `@declare_permission`，路径不命中 `_matchmaker_admin_permission` 任何关键词分支（[app/api/dependencies.py:404](../../../Xuanshiai/xuanshiai/app/api/dependencies.py)），也不在 `PERMISSION_EXEMPT_SUFFIXES`（dependencies.py:352-355），命中 fail-closed 分支。引入提交 `d8cbcd1`（2026-10-13），覆盖测试 `bafa20f`（2026-10-04）先存在，属真实回归。业务实现本身无问题（FOR UPDATE、验旧密、bcrypt 重哈希、审计均在 commit 前）。

- **预期效果**：后台账号恢复自助改密；权限覆盖测试收绿；运行时行为有测试兜底，杜绝同类回归。

### FIX-04 分身调用审计链路修复（AI-08）

- **问题**：`call_ai_provider`（[app/services/ai_avatar.py:419](../../../Xuanshiai/xuanshiai/app/services/ai_avatar.py)）超时/HTTP 错误分支（461-466 行）直接 `raise`，永不进入 470 行 `record_generation_audit`；成功审计的 `request_id` 为 472 行现场 `uuid4` 新生成，与入站请求无关联。无法按同一请求串联成功/失败/超时。
- **修改建议**：
  1. 将上游 `request_id`（无则生成一次）作为参数传入 `call_ai_provider`，成功与失败审计共用同一编号；
  2. 在超时、`HTTPError`、`ValueError`、`AiProviderError` 各分支 `raise` 前补失败审计（仅元数据：终态、耗时、provider、model、错误分类，不记原文）；
  3. 保持现有对外响应契约（504/503）与配额补偿行为不变。
- **预期效果**：分身调用可按请求追踪全生命周期；与主网关审计口径对齐。
- **验证**：单测覆盖成功/超时/供应商错误/无效响应四场景，断言审计记录同 `request_id` 且失败有终态记录。

### FIX-05 网关 token 用量透传（AI-09）

- **问题**：主网关 `_record` 硬编码 `token_usage=None`（[app/services/ai/gateway.py:335](../../../Xuanshiai/xuanshiai/app/services/ai/gateway.py)），376 行 `usage_cost` 因此恒空；语音网关同病（`app/services/voice/gateway.py:214`）。单次调用成本与业务总成本均不可核算。
- **修改建议**：
  1. 在 Provider 返回解析处提取供应商实际返回的 `usage`（deepseek/dots 均为 OpenAI 兼容格式），透传至 `GatewayCallRecord.token_usage`，保留来源与模型标识；
  2. Provider 未返回用量时记录"未知"（保持 `None` + 显式标记），**不得填零**；
  3. 语音网关音频场景无 token 概念，记录时长类用量元数据即可；
  4. 如需按任务聚合成本，以既有 `task_id`/`request_id` 关联，估算费用必须标记估算与价格版本。
- **预期效果**：主网关调用可核算成本，支持模型/Prompt 变更前后的成本对比。
- **验证**：单测覆盖有用量/缺失用量/重试/失败四场景；对外 API 响应不变。
