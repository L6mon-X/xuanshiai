# 微信绑定 / 解绑接口（A12-微信）

> 变更日期：2026-10-24　关联清单：`后端接口缺失清单.md` 第 389 行「绑定微信：`unionId`/`wechatOpenId` + 绑定/解绑接口，无接口」
> 口径：后台手动为会员关联/解除微信身份（`users.openid`/`unionid`/`wechat_bound_at`），**不新建列、不新建表**。

## 0. 背景与安全边界

- 微信登录以 `users.openid` 唯一定位账号（`login_wechat`：`WHERE openid=:openid`）。因此：
  - **绑定**要求 `openid` 全局唯一，不能抢占他人身份；
  - **解绑**若目标账号是「微信-only」（有 `openid`、无 `phone`），解除后将**无任何登录方式**，且下次扫码会另建新号——故接口**拒绝**这种情况并返回 409，要求先绑手机号。
- `openid` 属登录身份标识，**接口不回传、列表/详情也不回传原值**；详情只回布尔 `wechat_bound` 与 `wechat_bound_at`。
- 两者均为**敏感写**：`confirm=true` + `Idempotency-Key`。

## 1. 绑定微信

**`POST /api/v1/admin/matchmaker/members/{member_id}/wechat-binding`**

| 项 | 说明 |
|---|---|
| 权限 | `matchmaker.member.manage` |
| 状态码 | 成功 `200` |
| **敏感操作** | Header `Idempotency-Key`（8–128）且 Query `confirm=true`；缺 `confirm`→`428`，缺/非法键→`422` |
| 收口 | D-16 数据作用域；软删行不可操作（`FOR UPDATE`） |

Body `MemberWechatBindRequest`：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `openid` | string | 是 | 1–64 字 | 待绑定微信 openid（全局唯一） |
| `unionid` | string | 否 | ≤64 字 | 微信 unionid |
| `reason` | string | 是 | 1–255 字 | 绑定理由，记入审计 |

响应 `MemberWechatBindingResult`：`{ "member_id": 10086, "wechat_bound": true }`

| 状态码 | 场景 |
|---|---|
| `404` | 会员不存在或无权限 |
| `409` | 该 openid 已绑定其他会员 |
| `428` / `422` | 缺 `confirm` / 缺非法幂等键 |
| `503` | `users.openid`/`unionid` 列未就绪 |

## 2. 解绑微信

**`DELETE /api/v1/admin/matchmaker/members/{member_id}/wechat-binding`**

| 项 | 说明 |
|---|---|
| 权限 | `matchmaker.member.manage` |
| 状态码 | 成功 `200` |
| **敏感操作** | Header `Idempotency-Key` + Query `confirm=true`；缺 `confirm`→`428`，缺/非法键→`422` |

Query：`confirm=true`（必填）、`reason`（选填，默认「后台解绑」，1–255 字）

响应 `MemberWechatBindingResult`：`{ "member_id": 10086, "wechat_bound": false }`

| 状态码 | 场景 |
|---|---|
| `404` | 会员不存在或无权限 |
| `409` | 该会员未绑定微信 |
| `409` | 该会员未绑定手机号（解绑将无法登录，需先绑手机号） |
| `428` / `422` | 缺 `confirm` / 缺非法幂等键 |

## 3. 会员详情新增出参

`GET /api/v1/admin/matchmaker/members/{member_id}` 出参新增：

| 字段 | 类型 | 说明 |
|---|---|---|
| `wechat_bound` | bool | 是否已绑定微信（`openid` 非空即 true；缺列降级 false） |
| `wechat_bound_at` | datetime/null | 绑定时间（缺列降级 null） |

## 4. 待产品确认（诚实标注）

- 「绑定」要求操作者**已掌握用户 openid**（如从客服/其他系统迁移、或用户报出）。若期望的是**扫码授权绑定/换绑**流程，则需新增小程序侧 OAuth 换取 openid 的接口，属另一条链路，本次未实现。
- 解绑的手机号前置校验（防锁死）若与产品预期不符，可调整为「允许解绑但标记需重新登录」，需明确后修改。
