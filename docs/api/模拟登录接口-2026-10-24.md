# 模拟登录接口（A12-模拟登录）

> 变更日期：2026-10-24　关联清单：`后端接口缺失清单.md` A12「模拟登录（敏感）」
> 口径：**受限短时只读 token + 二次确认 + 全链路审计**（已与产品确认）。
> 安全约束优先：签发的是**只读**会话，任何写操作被中间件拒绝；不伪造/不冒充真实身份对外可见，仅用于后台排障查看会员视角。

## 1. 能力概述

- 管理员对**自己数据范围内**的会员签发一枚 **15 分钟、只读** 的 access token，用于以该会员视角查看页面。
- token 携带 `imp` 声明（值为发起管理员 ID）；网关侧只读中间件拦截所有非安全方法（`POST/PUT/PATCH/DELETE`）→ `403`。
- 会话落库到 `user_session`，新增列 `impersonated_by` 记录发起管理员；同时写 `business_audit_log`。
- 与积分/余额/钱包解耦：模拟登录不产生任何资金或数据变更。

## 2. 签发模拟登录会话

**`POST /api/v1/admin/members/{member_id}/impersonate`**

| 项 | 说明 |
|---|---|
| 权限 | `matchmaker.member.impersonate`（独立权限码，fail-closed） |
| 状态码 | 成功 `202` |
| 数据范围 | 仅可模拟 D-16 范围内的会员；越权/不存在 → `404` |
| **敏感操作** | 必须携带 Header `Idempotency-Key`（8–128）且 Query `confirm=true`。**缺 `confirm` → `428`；缺/非法幂等键 → `422`。** |
| 幂等 | 同键同载荷只签发一次；重放返回上次结果 |

### 请求

Path：`member_id`（正整数）
Query：`confirm=true`（必填）
Header：`Idempotency-Key: <8-128 chars>`（必填）

```http
POST /api/v1/admin/members/1001/impersonate?confirm=true
Authorization: Bearer <admin-access-token>
Idempotency-Key: imp-20261024-0001
```

### 响应 `ImpersonateSessionResponse`

| 字段 | 类型 | 说明 |
|---|---|---|
| `access_token` | string | JWT，含 `imp=<admin_id>` 声明，**只读** |
| `token_type` | string | `bearer` |
| `expires_in` | int | 有效期（秒），固定 900（15 分钟） |
| `impersonated_user_id` | int | 被模拟的会员 ID |
| `session_id` | int | 本次会话记录 ID |
| `read_only` | bool | 恒为 `true` |

### 错误码

| 状态码 | 触发条件 |
|---|---|
| `403` | 无 `matchmaker.member.impersonate` 权限 |
| `404` | `member_id` 不存在或不在当前账号数据范围内 |
| `409` | 目标会员状态非正常（`status != 1`），不可模拟 |
| `422` | 缺/非法 `Idempotency-Key` |
| `428` | 缺 `confirm=true` |

## 3. 只读约束（中间件行为）

- `app/main.py` 注册只读中间件 `enforce_impersonation_readonly`：对 `POST/PUT/PATCH/DELETE` 且 Bearer token 可解出 `imp` 声明的请求，直接返回 `403`（`模拟登录态为只读，不允许执行写操作`）。
- 判定在鉴权链路之前，纯无状态（仅解析 token 的 `imp` claim），不额外查库。
- 安全方法（`GET/HEAD/OPTIONS`）不受影响，可正常读取会员视角数据。

## 4. 数据变更与迁移

- 迁移目录：`migrations/user_impersonate/20261024_01_user_session_impersonated_by_{up,down,verify}.sql`

  - down：先删索引再删列（`IF` 条件，可回滚）。
  - verify：分段核对列/索引存在性。
- `database_setup_marriage.py`：`user_session` DDL 在 `revoke_reason` 与 `status` 间增列，`_ensure_required_columns` 增补齐条目镜像。
- **缺列降级**：签发时探测 `impersonated_by` 列是否存在——存在则 INSERT 带上该列，缺列则不带该列照常签发（迁移未执行环境不阻断，仅审计列缺省）。
