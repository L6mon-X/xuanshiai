# 平台用户登录日志（A12）管理后台接口

> 对应前端页面：账号管理 → 登录日志（`reg-user-log`）
> 路由文件：`app/api/routes/member_vip_admin.py`（前缀 `/admin/members`）
> 服务层：`app/services/member_vip_admin.py`
> 契约：`app/schemas/member_vip_admin.py`
> 数据源：`user_login_log`（**复用现有表，无补列/新表**）

平台用户登录日志此前只有「逐会员」查询 `GET /admin/members/{member_id}/behavior/login-logs`，
概览菜单需要的**跨全部平台用户**的登录日志列表、单条删除、一键清空均缺失。本轮补齐，
数据源仍是登录链路写入的 `user_login_log`（`login_type`：1 微信、2 手机号、3 测试登录；
`login_status`：1 成功、2 失败）。

---

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 全局前缀 | `/api/v1`（本文档路径均省略该前缀） |
| 鉴权 | `Authorization: Bearer <access-token>`，独立红娘后台 Token |
| 读权限 | `matchmaker.member.read` |
| 写权限（删除/清空） | `matchmaker.member.manage` |
| 数据范围 | 按 `resource_assignment` 对会员归属收口（D-16，`scope_exists_clause`，关联 `scope_assignment.user_id = u.id`）；`ALL`/`*` 不限 |
| 成功返回 | 不包 `data` 外壳，直接返回业务对象 |
| 分页结构 | `{ items, page, page_size, total, has_more }` |
| 错误返回 | `{"detail": "..."}` |
| 时间字段 | ISO 8601，服务端 `UTC_TIMESTAMP()` 写入 |

> **敏感操作（删除 / 清空）**：必须携带 `Idempotency-Key`（8–128）与 `confirm=true`；
> 缺幂等键 `422`，缺二次确认 `428`。同键重放返回上次结果，不重复删除。
> 删除/清空为物理删除（登录日志属流水，无软删列）；每类操作写一份 `business_audit_log`
> （`member.login_log.delete` / `member.login_log.clear`）。

## 2. `GET /admin/members/login-logs` — 平台用户登录日志列表

**基本信息**：跨全部（作用域内）平台用户的登录日志，倒序分页。需要 `matchmaker.member.read`；成功 `200`；无请求体。

**请求参数（query）**：

| 参数 | 类型 | 必填 | 默认 | 校验 | 含义 |
|---|---|---|---|---|---|
| `page` | int | 否 | 1 | `1-1000` | 页码 |
| `page_size` | int | 否 | 20 | `1-100` | 每页条数 |
| `search` | string | 否 | 无 | ≤64 | 昵称 / 手机号 / IP 模糊 |
| `login_status` | int | 否 | 无 | `1-2` | 1 成功、2 失败 |
| `login_type` | int | 否 | 无 | `1-3` | 1 微信、2 手机号、3 测试登录 |
| `start_date` | string | 否 | 无 | `YYYY-MM-DD` | 登录时间起（含） |
| `end_date` | string | 否 | 无 | `YYYY-MM-DD` | 登录时间止（含当日） |

**请求示例**：

```http
GET /api/v1/admin/members/login-logs?page=1&page_size=20&login_status=2&start_date=2026-10-01&end_date=2026-10-31
Authorization: Bearer <access-token>
```

**返回参数**：`items[]` 每项含 `id, user_id, nickname, phone, login_type, login_status, ip, device_id, platform, failure_reason, created_at`。`phone`、`login_type` 为本接口新增投影（旧逐会员接口不投影时为默认值）；`failure_reason` 仅失败日志有值。

**返回示例**：

```json
{"items":[{"id":10,"user_id":123,"nickname":"小林","phone":"138****0000","login_type":2,"login_status":1,"ip":"1.2.3.4","device_id":null,"platform":"ios","failure_reason":null,"created_at":"2026-10-20T09:00:00Z"}],"page":1,"page_size":20,"total":1,"has_more":false}
```

**错误**：`401` 未登录；`403` 缺少 `matchmaker.member.read`；`422` 分页/枚举/日期参数非法；`500` 数据库异常。

## 3. `DELETE /admin/members/login-logs/{log_id}` — 删除单条登录日志

**基本信息**：删除指定一条平台用户登录日志。需要 `matchmaker.member.manage`；**敏感操作**（`Idempotency-Key` + `confirm=true`，`operation` 为 `member.login_log.delete`）；成功 `200`。

**请求参数**：`log_id` 为 path 正整数。越权（日志所属会员不在数据范围内）或不存在统一返回 `404`，不泄露存在性。

```http
DELETE /api/v1/admin/members/login-logs/10?confirm=true
Authorization: Bearer <access-token>
Idempotency-Key: <8-128 chars>
```

**返回参数**：`{"deleted": 1}`。同键重放返回上次结果，不重复删除。

**错误**：`401`/`403`；缺 `Idempotency-Key` → `422`，缺 `confirm` → `428`；越权/不存在 → `404`。

---

## 4. `DELETE /admin/members/login-logs` — 一键清空登录日志

**基本信息**：按**当前筛选 + 数据范围**清空登录日志。需要 `matchmaker.member.manage`；**敏感操作**（`Idempotency-Key` + `confirm=true`，`operation` 为 `member.login_log.clear`）；成功 `200`。

**请求参数（query，均可选，与列表筛选一致，用于「清空当前筛选结果」）**：`search`、`login_status`、`login_type`、`start_date`、`end_date`。不传任何筛选即在作用域内清空全部。

```http
DELETE /api/v1/admin/members/login-logs?login_status=2&confirm=true
Authorization: Bearer <access-token>
Idempotency-Key: <8-128 chars>
```

**返回参数**：`{"deleted": N}`（本次实际删除行数）。写一份汇总审计（`resource_id` 为 `NULL`，原因记「后台清空登录日志 N 条」）。

**错误**：`401`/`403`；缺 `Idempotency-Key` → `422`，缺 `confirm` → `428`；`500` 数据库异常。
