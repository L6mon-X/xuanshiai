# 钱包余额调整接口（A12-钱包）

> 变更日期：2026-10-24　关联清单：`后端接口缺失清单.md` A12「用户余额-修改 / 钱包」
> 口径：**只做账本骨架**，复用 `account_ledger`，**不接真实支付、不新建表**（PROJECT_RULES §2.4）。
> 会员列表/详情新增的 `balance` 出参与 `sort_by=balance` 见 `docs/api/会员CRM列表接口.md`，与本文的余额口径同源（`finance.get_balance`）。

## 1. 概念与数据来源

- **余额（balance）** = `account_ledger` 中该用户 `account_type='user'`、`account_id=<user_id>`、`state='AVAILABLE'` 的 `SUM(CREDIT) − SUM(DEBIT)`，与 `get_balance` 完全同口径。
- **发放/充值** = 写入一条 `direction='CREDIT'` 的账本行；**扣减/调整** = 写入一条 `direction='DEBIT'` 的账本行。
- 与积分（`user_points`）是两套资金账，互不影响；本文只处理余额。
- 每条调整写入 `source_type='admin_balance_adjust'`、`state='AVAILABLE'`，幂等键 `balance-adjust:{admin_id}:{user_id}:{direction}:{amount}:{reason}`。

## 2. 批量余额调整（发放 / 扣减）

**`POST /api/v1/admin/finance/balance-adjustments`**

| 项 | 说明 |
|---|---|
| 权限 | `finance.write` |
| Content-Type | `application/json` |
| 状态码 | 成功 `201` |
| **敏感操作** | 必须携带 Header `Idempotency-Key`（8–128）且 Query `confirm=true`。**缺 `confirm` → `428`；缺/非法幂等键 → `422`。** |
| 幂等 | 同键同载荷只执行一次；重放直接返回上次结果，不重复入账/扣减 |

### 请求

Query：`confirm=true`（必填）
Header：`Idempotency-Key: <8-128 chars>`（必填）

Body `BalanceAdjustmentRequest`：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `user_ids` | array[int] | 是 | 1–5000 项，去重、均为正整数 | 目标用户 ID 列表 |
| `direction` | string | 是 | `CREDIT` \| `DEBIT` | CREDIT 发放/充值，DEBIT 扣减/调整 |
| `amount` | Decimal | 是 | `>0`、`≤1000000`、2 位小数 | **每人**调整金额（元） |
| `reason` | string | 是 | 1–20 字 | 调整理由，记入审计 |

```http
POST /api/v1/admin/finance/balance-adjustments?confirm=true
Authorization: Bearer <access-token>
Idempotency-Key: bal-adj-20261024-0001
Content-Type: application/json

{"user_ids":[1001,1002],"direction":"CREDIT","amount":"50.00","reason":"活动补偿"}
```

### 响应 `BalanceAdjustmentResult`

| 字段 | 类型 | 说明 |
|---|---|---|
| `direction` | string | 回显 `CREDIT`/`DEBIT` |
| `adjusted_count` | int | 实际写入账本的账户数 |
| `total_amount` | Decimal | `adjusted_count × amount` |
| `sample_ledger_ids` | array[int] | 前 10 条 `ledger.id` 样本 |
| `target_user_ids` | array[int] | 实际命中的 `user_id` 列表 |

### 业务规则与错误码

- 目标用户须存在且 `status=1`（有效）；命中集合按 `FOR UPDATE` 加行锁，防并发重复调整。
- **`DEBIT` 扣减前逐户校验可用余额**：任一账户余额不足则**整批 `409`，不产生部分扣减**。
- 全部成功在一个事务内提交；写一份 `business_audit_log`（`action='finance.balance_adjust'`）。

| 状态码 | 触发条件 |
|---|---|
| `422` | 缺/非法 `Idempotency-Key`、Body 校验失败（空/超 5000/金额越界/reason 超限） |
| `428` | 缺 `confirm=true` |
| `403` | 无 `finance.write` 权限 |
| `404` | `user_ids` 全部无效（不存在或已注销） |
| `409` | `DEBIT` 时至少一个账户可用余额不足（整批回滚） |

## 3. 按用户查询钱包余额与流水

**`GET /api/v1/admin/finance/user-wallet/{user_id}`**

| 项 | 说明 |
|---|---|
| 权限 | `finance.read` |
| 状态码 | 成功 `200` |
| 数据范围 | 受 D-16 数据范围约束；目标用户不在当前账号可见范围内 → `404` |

Query：`page`（默认 1，`≥1`）、`page_size`（默认 20，1–100）

### 响应 `UserWalletResponse`

| 字段 | 类型 | 说明 |
|---|---|---|
| `account_type` | string | 固定 `user` |
| `account_id` | int | 用户 ID |
| `pending_amount` | Decimal | 待用（非 AVAILABLE）金额汇总 |
| `available_amount` | Decimal | 可用余额（= balance） |
| `ledger` | `LedgerEntryPage` | 分页流水：`items[{id, account_type, account_id, direction, amount, state, source_type, source_id, idempotency_key, created_at}]` + `page/page_size/total/has_more` |
